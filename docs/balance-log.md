신뢰 라벨: [측정] 로그나 시뮬레이션에서 직접 센 값, [추정] 표본이 작은 해석, [미확인] 근거 없음.
봇 시뮬레이션은 사람 플레이가 아니다. 규칙이 얼마나 느슨한지 보는 용도이다.

## v0.1 기준선 (2026-10-14)

설정: 9x9, 시작 중앙(4,4), 이동 1.5칸/초, 자기장 7x7(30초, 5/초) → 5x5(70초, 8/초) → 3x3(110초, 12/초).

| 봇 | 클리어 | 사망 단계(1/2/3) |
|---|---|---|
| 가만히 있기 | 101/500 | 0/0/399 [측정: 봇] |
| 예고를 보고 다음 영역으로 이동 | 500/500 | 0/0/0 [측정: 봇] |
| 영역이 줄어든 뒤에야 이동 | 500/500 | 0/0/0 [측정: 봇] |

관찰(사실):
- 중앙에 있으면 1단계(7x7)와 2단계(5x5) 영역은 어떤 시드에서도 중앙을 포함한다. 가만히 있는 봇이 3단계 전에는 한 번도 피해를 받지 않았다(사망 399판 모두 3단계).
- 조금이라도 움직이는 봇은 500판 모두 클리어했다. 수치표 목표(클리어율 약 40%)와 가만히(20%)~움직임(100%) 사이에 중간 난이도가 없다.

해석 [추정]: 시작이 최종 영역과 가까워 이동 압박이 거의 없다. 사람 플레이 기록이 없으므로 사람에게도 쉬운지는 [미확인].

## v0.2 후보 1: 시작 위치 변경 (2026-10-14)

- 수정 전: 시작 위치 중앙(4,4) 고정
- 수정 후: 최종 안전 영역에서 가장 먼 모서리(거리가 같으면 목록 순서 (0,0),(8,0),(0,8),(8,8) 중 앞선 것)
- 이유: 최종 영역까지 이동해야 하는 거리를 만들어 1~3단계가 실제로 위협이 되게 한다.
- 바꾼 뒤 결과 (v0.2, 자동 테스트 26개 통과):

|---|---|---|
| 가만히 있기 | 0/500 | 499/1/0 [측정: 봇] |
| 예고를 보고 다음 영역으로 이동 | 500/500 | 0/0/0 [측정: 봇] |
| 영역이 줄어든 뒤에야 이동 | 500/500 | 0/0/0 [측정: 봇] |

관찰(사실):
- 가만히 있기는 클리어 101판에서 0판으로 바뀌었고, 거의 전부 1단계에서 죽는다(499/500). 시작 위치가 영역 밖이라 이동이 필수가 됐다.
- 움직이는 두 봇은 여전히 500/500 클리어. 이동 거리가 늘었어도 1단계 시작(30초)까지 걸어갈 시간이 충분하다.

판단 [추정, 봇 기준]: 후보 1은 "아무것도 안 하면 이긴다"는 허점을 없앴지만 움직이는 플레이의 난이도는 올리지 못했다. 다음 후보는 이동 압박(이동 속도 하향, 피해 상향, 맵 확대 등) 중 하나를 하나씩 시험한다. 사람 플레이 기록은 아직 없다 [미확인].

## v0.3 엔진 교체: 2D 큰 지도 (2026-10-21)

밸런스 수정이 아니라 규칙 엔진 교체다. 9x9 칸에서 200x200m 연속 지도로 바꿨으므로 v0.1, v0.2와 숫자를 직접 비교하지 않는다.

- 수정 전: 9x9 격자, 칸 단위 이동(1.5칸/초), 사각형 안전 영역(7x7, 5x5, 3x3), 아이템 15초마다 1개
- 수정 후: 200x200m 연속 지도, 6m/s 이동, 원형 안전 영역(반지름 142 -> 90 -> 50 -> 20m, 30/70/110초에 20초 동안 줄어듦, 피해 5/8/12 HP/초), 장애물 40개, 아이템 6초마다 1개(동시 8개, 수명 45초, 획득 반경 2m), 시작은 최종 원에서 가장 먼 모서리 안쪽 5m
- 이유: 격자 9x9는 너무 작아 이동 압박이 거의 없었고(v0.2까지의 관찰), 지도에서 보면서 움직이는 배틀로얄 형태로 설계 의도를 보여주기 위해.
- 구현: 자동 테스트 41개 통과, 화면(카메라, 미니맵, 장애물, 아이템, 자기장 원)은 브라우저에서 직접 확인.

봇 시뮬레이션 (시드 1~500, `node docs/balance/bot-sim.mjs`) [측정: 봇, 사람 아님]:

| 봇 | 클리어 | 사망 단계(1/2/3) | 평균 생존 |
|---|---|---|---|
| 가만히 있기 | 0/500 | 500/0/0 | 52.7초 |
| 예고를 보고 다음 원 중심으로 이동 | 500/500 | 0/0/0 | 180.0초 |
| 자기장 밖으로 밀려난 뒤에야 이동 | 0/500 | 0/500/0 | 73.5초 |

관찰(사실):
- 예고(10초 전 다음 원 표시)를 보고 미리 움직이는 봇은 500판 모두 클리어한다. 반대로 밖으로 밀려난 뒤에야 반응하는 봇은 500판 모두 2단계에서 죽는다.
- 이전 버전(v0.2)에서는 움직이기만 하면 모두 클리어였지만 이번에는 "얼마나 일찍 반응하느냐"에 따라 결과가 갈린다.
- 봇은 아이템을 쓰지 않고, 장애물을 우회하지 못해 막히면 옆으로 비켜 걷는 단순한 규칙이다.

해석 [추정, 봇 기준]: 선행 이동이 승패를 가른다. 완벽한 선행 이동은 모두 클리어하므로, 실제 사람의 클리어율은 0%와 100% 사이 어딘가일 것이다. 목표(약 40%)와 가까운지는 사람 플레이 기록 없이는 [미확인]. 다음 수정 후보는 예고 시간(10초), 이동 속도(6m/s), 단계별 피해량이며 사람 기록을 본 뒤 한 번에 하나만 바꾼다.

## v0.3 직접 플레이 관찰 (2026-10-22, 자체 플레이 1명, 소표본)

플레이어: 본인(self) 1명, 판 수 미기록. 사람 기록이 아니라 구두 관찰이다. [추정]

- "자기장은 누구라도 피하겠다. 방해하는 요소가 있어야 한다." → 현재 규칙에는 자기장 외 위협이 없어 이동만 하면 난이도가 낮다. 봇 결과(예고를 보고 이동하는 봇 500/500)와 방향이 같다.
- "아이템이 뭔지 안 알려줘서 모르겠다." → 플레이 화면에 아이템 설명이 없다(시작 화면에만 있음). 정보 표시 문제이며 규칙 수치와는 무관하다.
- "아이템 지속시간이 짧은 것 같다." → 가속 8초, 보호 5초. 효과 남은 시간이 화면에 없어 체감이 짧아졌을 수 있다. 수치 변경은 사람 기록 전까지 보류.

## v0.4 폭격과 추적자 추가, 안내 표시 (2026-10-22)

- 이유: 직접 플레이 관찰("자기장은 누구라도 피한다", 자체 플레이 1명 [추정])과 v0.3 봇 결과(예고를 보고 이동하는 봇 500/500)에서 자기장 외의 위협이 없었다. 목표 클리어율을 약 40%에서 약 15~20%로 낮췄다(가설, 사람 기록 전까지 [미확인]).
- 수정 전: 위협은 자기장뿐, 보호는 자기장 피해만 막음, 플레이 화면에 아이템 설명과 남은 시간 표시 없음
- 수정 후:
  - 폭격: 20초부터 8초마다, 플레이어 주변 14m 안에 반경 6m 원 2/3/4/5개(자기장 0~3단계), 2.5초 뒤 폭발해 안에 있으면 피해 35
  - 추적자: 40초부터 20초마다 1마리(동시 최대 4, 수명 45초), 속도 4.5m/s, 닿으면 초당 20 피해, 장애물 통과 불가
  - 보호 아이템이 폭격과 추적자 피해도 막음
  - 로그에 사망 원인(zone, bomb, chaser)과 원인별 받은 피해 추가, 리포트에 사망 원인 집계
  - 플레이 화면: 아이템과 위협 안내, 가속·보호 남은 시간, 피해를 입으면 화면 테두리가 붉게 깜빡임
- 구현: 자동 테스트 62개 통과.

## v0.5 추적자 처치(폭격이 추적자도 맞춘다), 한 줄 의견 저장 (2026-10-22)

- 이유: "보라 추적자를 죽일 방법이 없다"는 플레이 소감(자체 플레이 1명 [추정]). 피하기만 하는 규칙에 능동적인 선택(추적자를 폭격 원으로 끌어들이기)을 더하기 위해.
- 수정 전: 추적자는 수명(45초)이 다할 때까지 사라지지 않음
- 수정 후: 폭격이 터질 때 원 안(중심 거리 ≤ 반경 6m)에 있는 추적자는 사라진다. 처치 수(chasersKilled)를 기록한다.
- 구현: 자동 테스트 76개 통과. 한 줄 의견은 별도 테이블(run_notes)로 저장(판 기록은 결과 화면에서 즉시 저장).

해석 [추정, 봇 기준]: 추적자가 죽으면 동시 4마리 한도에 빈자리가 생겨 새 추적자가 더 자주 채워지는 것이 한 원인일 수 있다(확인하지 않음). 사람이 의도적으로 끌어들여 처치한다면 결과는 다를 수 있으나 [미확인]. 사람 기록(A, B, C의 사망 원인과 chasersKilled)을 본 뒤 추적자 수, 속도, 피해 중 하나만 바꾼다.

## v0.6 추적자 늘리기 (2026-10-22)

- 이유: 직접 플레이 소감 "추적자를 죽일 수 있으니 쉽다, 추적자를 늘려도 될 것 같다" (자체 플레이 1명, 개발자 본인이라 숙련된 플레이어 [추정]). 한 사람의 의견이므로 크게 올리지 않고 사람 기록으로 다시 확인한다.
- 수정 전: 추적자 생성 간격 20초, 동시 최대 4마리
- 수정 후: 생성 간격 12초, 동시 최대 6마리 (둘 다 "추적자 밀도"라는 하나의 요소를 올리는 값이라 한 항목으로 묶어 바꿨다. 효과를 둘로 나눠 보지는 못한다.)
- 구현: 자동 테스트 84개 통과.

관찰(사실):
- 추적자를 늘렸는데 가장 똑똑한 봇의 클리어율은 오히려 소폭 올랐다(4.4% → 5.6%). 봇은 사람과 달리 폭격에 휘말린 추적자가 늘어 우연히 더 많이 죽는 경우가 있을 수 있으나 원인은 확인하지 않았다.
